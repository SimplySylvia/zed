## Build environment notes (important — see also memory / [[zed-build-environment]])

Three environment blockers were fixed to get a clean build (none are code issues):

1. **rustup 1.95.0 was corrupted** (missing `rustc` + host `rust-std`; stale
   `~/.rustup/tmp`). Reinstalled cleanly.
2. **`cmake` missing** (needed by `wasmtime-c-api`). Homebrew downloads are blocked in this
   environment (ghcr.io times out), so `cmake` 3.30.5 was installed from Kitware's GitHub
   release into `~/.local` (symlinks in `~/.local/bin`).
3. **Full Xcode + Metal toolchain missing** (`gpui_macos` compiles Metal shaders). Xcode
   was installed; the Metal toolchain is a separate component on Xcode 16.3+
   (`xcodebuild -downloadComponent MetalToolchain`).

**Build invocation:** `xcode-select` still points at the CommandLineTools, so builds set
`DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer` and
`PATH="$HOME/.local/bin:$HOME/.cargo/bin:$PATH"`. **Recommended permanent fix** (removes
the need for `DEVELOPER_DIR`): `sudo xcode-select -s /Applications/Xcode.app/Contents/Developer`.

Cold `cargo build -p zed` compiled the workspace in a few minutes; an incremental rebuild
after a one-file change was ~13s.

## Surprises / deviations from the M0 plan

- The **"~2-line fork diff" was ~4 upstream files** (`Cargo.toml`, `crates/zed/Cargo.toml`,
  `main.rs`, `zed.rs`) as the study notes predicted. Still tiny and fully additive
  otherwise. Tracked in `FORK_DIFF.md`.
- A **borrow-checker fix** was needed in the `zed.rs` `join!`: the gated `async` block
  captured `workspace_handle` by reference, conflicting with its move into
  `initialize_agent_panel`. Resolved by binding owned clones and using `async move`.
- M0 was a panel only (per sign-off). The Plan **tab** (`Item`/`SerializableItem`) and
  thread-following arrive in M3.
