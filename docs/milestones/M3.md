## What works (built)

- **`PlanView`** — a center-pane `Item` singleton (`items_of_type` reuse); tab shows a
  lifecycle status dot (state-matrix colors) + `Plan — <id>`, or the exact empty-state copy
  "no plan — ask the agent to draft one".
- **Thread-following** — subscribes to `AgentPanel::ActiveViewChanged` and retargets to the
  active thread's plan, keyed by the **ACP session id** (`active_agent_thread().session_id()`,
  matching `plan.thread`). `.plans/` resolves under the first visible worktree.
- **Tasks lens** — task cards (state-colored borders, status-glyph checkbox vocabulary,
  title, ticket/system/guard/sha chips, step rows with per-step guard chips), all via
  `cx.theme()`.
- **Lens switcher + Spec/Design** — Spec (goal/scope/acceptance) and Design (contracts/
  decisions/risks) as styled text; default lens follows status.
- **Live reload** — 500ms GPUI-executor poll re-reads the bound plan and re-renders only on
  change (the demo: watch the agent draft into the tab).
- **Serialization** — `SerializableItem` restores the tab on relaunch; it re-binds to the
  restored active thread (no per-item payload; `cleanup` no-op).

card/steps/guards, §3.8 Spec/Design blocks.

  `zed-notes.md`). Seam: the agent must stamp `plan.thread` with the session id.
