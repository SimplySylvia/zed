## What works (verified)

- **Typed schema** (`schema.rs`, 28 structs) mirroring PRD Appendix A, GPUI-free. `Status`
  and `TaskStatus` are typed enums; smaller open-ended codes (`op`, `system`, `severity`,
  guard kind, …) stay `String` for forward-compat, to be refined as the UI needs them.
- **Lossless round-trip** — the LED-212 fixture parses to the expected typed model with
  **no unmodeled fields** (proving every Appendix A field is typed) and re-serializes as a
  stable fixed point.
- **Unknown-field preservation** — every object carries `#[serde(flatten)] extra`, so a
  field written by a newer schema survives load→save (§11).
- **`migrate()`** — a missing `schema_version` is treated as current (lenient, per sign-off
  Q1); a newer version is rejected with a clear error; ordered migrations slot in for older
  versions as the schema evolves. `load` migrates before typed deserialization.
- **Atomic persistence** (`store.rs`) — `save` backs up the prior revision to
  `.bak/<id>.rev<N>.plan.json` (capped at 10), writes a temp file, `sync_all`s it, and
  renames over the target (atomic within a filesystem; a crash never tears the file).
  `load` errors — never panics — on missing/malformed files.
- **Referential-integrity validation** (`Plan::validate`) — flags dangling `acceptance.tasks`,
  `task.depends_on`, `task.acceptance`, and executor/plan thread mismatch as **non-fatal
  warnings** (per sign-off Q3), so a broken plan stays loadable and repairable.

## Decisions (per M1 sign-off)
- Errors via `anyhow` (no custom `error.rs`); a typed `PlanError` arrives when `plan_ui`/
  `plan-server` need to branch on error kind (M3+).
- `.bak` retention: keep newest 10 by rev.
- Validation issues are warnings; only structural/serde errors are fatal on load.
- Fixture authored from Appendix A (no HTML-demo prose was required).
